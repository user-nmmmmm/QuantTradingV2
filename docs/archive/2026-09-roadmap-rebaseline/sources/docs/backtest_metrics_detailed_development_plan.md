> 制定日期：2026-08-02  
> 上位路线图：[unified_roadmap.md](unified_roadmap.md)
>
> 执行计划：[development_plan.md](development_plan.md)

> 历史需求来源：[backtest_metrics_development_roadmap.md](archive/2026-08-roadmap-consolidation/backtest_metrics_development_roadmap.md)

> 目标：把 BM0–BM6 从指标清单拆成可实现、可测试、可验收的工程任务。

## 1. 开发目标

本轮开发不以“增加更多数字”为唯一目标，而是建立一套可信、可解释、可扩展的回测分析体系：

1. 修正现有指标的计算口径与边界行为。
2. 确保资金、持仓、成交和权益曲线能够相互对账。
3. 补齐风险、收益质量、资金使用效率和策略归因指标。
4. 为每个指标保存计算状态、样本数、单位和参数，避免把“无法计算”显示成 0。
5. 建立单元测试、场景测试和回归基线，保证后续优化策略时可以可信比较。

## 2. 完成标准（Definition of Done）

一项指标只有同时满足以下条件，才可以在 roadmap 中标记完成：

- 公式、输入数据、单位、年化方式和边界情况已经明确。
- 核心计算与报告展示解耦，计算层不直接格式化字符串。
- 对正常、空样本、单样本、零波动、全胜、全败和异常输入均有测试。
- JSON 输出不包含 `NaN`、`Infinity` 或 `-Infinity`。
- 不可计算值返回 `null`，并附带明确状态或原因，不伪装成 0。
- 报告中同时显示关键指标值、样本数、统计周期和必要的计算参数。
- 新旧回测结果差异经过解释，并更新回归测试基线。
- 文档包含定义、公式、解释方法和使用限制。

## 3. 总体技术设计

### 3.1 数据流

```text
行情数据
  -> 策略信号
  -> 订单与成交
  -> 持仓/现金账本
  -> 权益快照
  -> 标准化收益序列和已平仓交易
  -> 指标计算器
  -> 结构化结果
  -> JSON / 控制台 / 图表报告
```

指标计算器只能读取标准化输入，不应修改原始 `equity_curve`、交易列表或持仓对象。

### 3.2 建议的数据契约

每个指标建议输出统一结构：

```python
{
    "value": 1.23,               # 无法计算时为 None
    "status": "ok",             # ok / insufficient_data / undefined / not_modeled
    "reason": None,              # 非 ok 时提供机器可读原因
    "unit": "ratio",            # ratio / percent / currency / days / trades
    "sample_size": 120,
    "periods_per_year": 252,
    "parameters": {}
}
```

为了兼容已有调用方，可以先保留旧的扁平字段，同时新增 `metric_details`；待报告和测试迁移完成后再移除旧接口。

### 3.3 统一计算约定

- 权益收益默认使用相邻权益快照的简单收益率；如引入对数收益，必须使用不同字段名。
- 年化周期不得固定写死为 252，必须由数据频率推断或配置明确指定。
- 百分比在计算层使用小数，例如 `0.12` 表示 12%；格式化仅发生在展示层。
- 费用、佣金和滑点均进入成交后的现金账本，不允许只在报告阶段估算扣除。
- 已平仓交易指标只使用完整 round-trip 交易；未平仓头寸单独报告。
- 无风险利率、基准收益、置信水平和年化周期都必须保存在结果元数据中。

## 4. 分阶段实施计划

## 阶段 A：BM0 指标可信度与数据契约（最高优先级）

目标：先保证现有指标“算得对、说得清、能对账”，否则后续高级指标没有可信基础。

### A1. 年化周期与收益序列（BM0-01、BM0-02）

实现内容：

- 增加 `periods_per_year` 配置，允许显式设置。
- 未显式设置时，根据权益时间戳中位间隔推断日线、小时线或分钟线频率。
- 时间间隔不规则或样本不足时，不自动猜测，返回说明并要求配置。
- 统一生成收益序列，过滤首个无收益点，但保留有效的 0 收益。
- 夏普率、索提诺率、波动率和 CAGR 共同使用同一套年化元数据。

验收标准：

- 日线、小时线使用不同年化周期时结果符合手工计算。
- 不规则时间序列不会静默采用 252。
- 所有年化指标返回所用的 `periods_per_year`。

### A2. 滑点和交易成本口径（BM0-03）

实现内容：

- 明确滑点参数单位：基点、百分比或绝对价格，禁止同一字段支持多种隐含语义。
- 买入成交价向上偏移，卖出成交价向下偏移。
- 佣金与滑点分别累计，并输出总交易成本。
- 检查止损、止盈、普通平仓与强制平仓是否使用相同成交模型。

验收标准：

- 在相同行情与信号下，提高成本后净收益不得提高。
- 单笔买卖的成交价、佣金、滑点成本和净 PnL 可以手工对账。
- 报告同时显示毛收益、总成本和净收益。

### A3. 已平仓交易数据完整性（BM0-04）

实现内容：

- 为每笔完整交易保存入场/出场时间、价格、数量、方向、毛 PnL、费用、净 PnL、收益率、持有时长和退出原因。
- 建立稳定的 `trade_id`，将开仓、加仓、减仓和平仓事件关联起来。
- 明确定义部分平仓的记账方式，并在测试中固定 FIFO、LIFO 或平均成本法。

验收标准：

- 交易级 PnL 汇总与账户已实现 PnL 一致。
- 胜率、盈亏比、期望值只读取标准化的已平仓交易。
- 缺少入场或出场信息的记录不会进入已平仓样本。

### A4. 不可计算值与序列化（BM0-05、BM0-06）

实现内容：

- 将“真实计算结果为 0”和“无法计算”分开。
- 夏普率在零波动、样本不足时返回 `null` 及原因。
- Profit Factor 在无亏损交易时不输出无穷大，改为 `null` 或受控状态。
- 在统一序列化入口清理非有限浮点数。

验收标准：

- 标准 JSON 编码器可直接序列化全部报告。
- 前端或控制台能区分 0、未建模、未定义和样本不足。

### A5. 月收益算法修正（BM0-07）

实现内容：

- 先按月取得期初、期末权益，再计算月度复合收益。
- 月份边界使用真实时间戳，不能按固定 30 天切分。
- 对无交易但有权益快照的月份保留 0 收益。
- 对首月数据不完整的情况增加标记。

验收标准：

- 跨月、跨年、闰年和缺失交易日场景均符合手工结果。
- 月收益复合后可与期间总收益完成容差内对账。

### A6. 权益曲线纯函数化（BM0-08）

实现内容：

- 审计所有指标函数，禁止排序、补点或格式化时原地修改输入权益曲线。
- 指标入口复制必要字段并完成排序、去重和校验。
- 对重复时间戳制定规则：拒绝、保留最后值或按事件聚合，并记录选择。

验收标准：

- 计算指标前后的原始权益曲线深度比较完全一致。
- 调换指标计算顺序不会改变最终结果。

### A7. 期末资金与未平仓头寸对账（BM0-09）

实现内容：

- 报告期末现金、持仓市值、未实现 PnL、已实现 PnL、累计费用和总权益。
- 默认采用盯市方式计入未平仓头寸；如选择期末强制平仓，必须单独配置和标记。
- 增加资金恒等式校验：`期末权益 = 现金 + 持仓市值`。
- 增加收益归因校验：初始资金、已实现/未实现 PnL、费用和资金流能够对账。

验收标准：

- 无持仓、单持仓、多持仓、部分平仓和期末未平仓场景全部通过。
- 对账误差超过货币精度容差时，回测明确失败或产生高优先级告警。

### 阶段 A 测试清单

- 纯现金、无交易。
- 单笔盈利、单笔亏损。
- 全胜、全败、盈亏相抵。
- 零波动权益曲线。
- 只有一个权益点或一笔交易。
- 部分平仓与期末未平仓。
- 跨月、跨年、缺失日期、不规则周期。
- 手续费为 0、高手续费、滑点为 0、高滑点。
- 重复时间戳和乱序输入。

## 阶段 B：BM1 回撤风险分析

目标：从单一最大回撤比例扩展到可定位、可解释的回撤事件。

实现内容：

- BM1-01：最大回撤开始日期（峰值日期）。
- BM1-02：最大回撤谷底日期。
- BM1-03：恢复日期；回测结束仍未恢复时返回 `null` 和 `unrecovered`。
- BM1-04：下跌期、恢复期和总水下时长。
- BM1-05：最长水下期及其起止日期。
- BM1-06：Top-N 回撤事件表，避免只看一次最大回撤。

算法要求：

- 使用运行峰值计算水下曲线。
- 回撤事件从权益跌破历史峰值开始，到重新达到或超过峰值结束。
- 日期跨度和观测周期数分别保存，避免把交易日和自然日混淆。

验收标准：

- V 型恢复、长期横盘、创新高后再回撤和未恢复场景符合预期。
- 最大回撤比例与现有指标在相同口径下保持一致。
- 图表能够标注峰值、谷底和恢复点。

## 阶段 C：BM2 交易质量与收益质量

目标：解释收益由什么样的交易分布产生，避免仅依赖胜率。

实现内容：

- BM2-01：平均盈利、平均亏损。
- BM2-02：盈亏比（平均盈利 / 平均亏损绝对值）。
- BM2-03：最大单笔盈利、最大单笔亏损。
- BM2-04：期望值同时输出货币值、每单位风险 R 倍数和百分比。
- BM2-05：盈利、亏损交易持有时长分布。
- BM2-06：连续盈利、连续亏损次数及对应 PnL。
- BM2-07：交易 PnL 的中位数、分位数和标准差。
- BM2-08：胜率置信区间，明确小样本不确定性。
- BM2-09：Profit Factor 继续显示原值，同时展示样本量和毛亏损。
- BM2-10：对极端 Profit Factor 增加状态、展示上限或警告，但不篡改原始统计。

验收标准：

- 所有交易类指标同时输出总样本数、盈利数和亏损数。
- 全胜、全败、只有一笔交易时不会产生无穷大或误导性 0。
- 货币期望值能够用 `胜率 × 平均盈利 + 败率 × 平均亏损` 复算。

## 阶段 D：BM3 资金暴露与使用效率

目标：解释策略为何交易少，以及有限资金和时间是否被有效使用。

实现内容：

- 时间暴露率：账户存在持仓的时间占比。
- 资金暴露率：持仓市值或风险资金相对权益的平均值、峰值和分位数。
- 市场参与天数、空仓天数、平均同时持仓数和最大同时持仓数。
- 资金周转率和年化换手率。
- 每单位暴露收益、每单位风险收益。
- 信号漏斗：原始信号数、通过过滤器数、下单数、成交数、完成交易数。

验收标准：

- 能明确区分“没有信号”“信号被过滤”“资金不足”“订单未成交”和“仍未平仓”。
- 空仓策略的暴露率为 0，而不是不可计算。
- 多标的持仓重叠时按时间加权正确聚合。

## 阶段 E：BM4 成本与执行敏感性

目标：判断策略利润是否足以覆盖真实执行摩擦。

实现内容：

- 毛 PnL、佣金、滑点、其他费用和净 PnL 分解。
- 成本占毛利润、成交额和初始资金的比例。
- 基准、低成本、高成本三种情景回测。
- 滑点和佣金参数网格，输出净收益、最大回撤和交易数敏感性。
- 如当前引擎不支持成交量或盘口冲击，明确标记 `not_modeled`。

验收标准：

- 成本增加时，订单和行情不变条件下净 PnL 单调不增。
- 每个成本情景保存完整参数，结果可重现。
- 报告明确区分已建模成本和未建模成本。

## 阶段 F：BM5 策略、标的与退出原因归因

目标：识别哪些策略组件真正贡献收益和风险。

实现内容：

- 交易保存入场策略、触发信号、退出策略和退出原因。
- 按策略、标的、方向和退出原因统计交易数、胜率、净 PnL、Profit Factor、回撤贡献和持有期。
- 对多策略共同参与的交易制定明确归因规则；第一版可先采用主策略标签并保存辅助标签。
- 增加贡献总和校验，归因后的 PnL 必须与组合 PnL 对账。

验收标准：

- 止损退出不能错误归入普通策略退出。
- 入场归因和退出归因分别报告。
- 所有归因分组汇总与整体数据一致。

## 阶段 G：BM6 稳健性、基准与参数分析

目标：从“历史样本表现好”升级为“结果具有一定稳健性证据”。

实现内容：

- 与买入持有或指定基准比较：超额收益、跟踪误差、信息比率、Beta 和 Alpha。
- 滚动收益、滚动波动率、滚动夏普和滚动最大回撤。
- 按年、季度和市场状态分段统计。
- 参数敏感性：关键参数邻域网格，不只报告最佳点。
- 样本内/样本外切分，并保存切分时间和参数选择过程。
- 后续可选：walk-forward 和交易顺序 Monte Carlo；这两项应独立排期，避免首版范围膨胀。

验收标准：

- 基准时间索引对齐规则明确，不用未来数据填补历史缺口。
- 样本外参数不得使用样本外数据调优。
- 参数分析报告最佳值附近是否形成稳定平台，而不是只挑单一峰值。

## 5. 开发顺序与依赖关系

```text
BM0 数据契约、收益序列、交易账本、资金对账
  ├─> BM1 回撤分析
  ├─> BM2 交易质量
  ├─> BM3 暴露与效率
  └─> BM4 成本敏感性
          └─> BM5 策略归因
                  └─> BM6 稳健性与基准分析
```

建议严格先完成 BM0。BM1 和 BM2 可在 BM0 验收后并行；BM3 依赖可靠的持仓快照；BM4 依赖统一成交成本；BM5 依赖完整交易标签；BM6 依赖前述指标已经稳定。

## 6. 建议迭代安排

以下为单人开发的相对估算，不代表固定日历承诺：

| 迭代 | 范围 | 预计工作量 | 主要交付物 |
|---|---|---:|---|
| Sprint 1 | BM0-01～BM0-06 | 3–5 天 | 统一收益序列、年化配置、成本语义、空值规范 |
| Sprint 2 | BM0-07～BM0-09 | 3–5 天 | 月收益、纯函数指标、期末权益对账 |
| Sprint 3 | BM1 + BM2 基础项 | 4–6 天 | 回撤事件、交易质量指标、边界测试 |
| Sprint 4 | BM3 + BM4 | 4–7 天 | 暴露漏斗、成本分解和敏感性分析 |
| Sprint 5 | BM5 | 3–5 天 | 策略/标的/退出归因及对账 |
| Sprint 6 | BM6 | 5–8 天 | 基准、滚动、分段和参数稳健性报告 |

每个 Sprint 结束都应生成一份固定数据集回测报告，并与上一个版本做结构化差异比较。

## 7. 测试策略

### 7.1 单元测试

- 每个公式使用可手算的小型固定数组。
- 使用参数化测试覆盖正常值、边界值和不可计算值。
- 浮点比较使用明确容差，货币对账使用货币精度容差。
- 验证函数不修改输入对象。

### 7.2 场景测试

- 构造确定的价格序列和交易事件，验证从成交到最终报告的全链路结果。
- 覆盖长仓、短仓、加仓、减仓、反向、止损、止盈及期末未平仓。
- 验证手续费和滑点在成交、交易 PnL、账户权益三个层次保持一致。

### 7.3 回归测试

- 选择至少三个固定回测样本：无交易、小规模可手算、真实历史样本。
- 保存关键配置、数据摘要和期望指标快照。
- 对有意改变口径的任务，先记录旧值、新值和差异原因，再更新基线。
- 避免直接对整个报告文本做脆弱快照；优先比较结构化字段。

### 7.4 性质测试

- 成本增加，净收益不应增加。
- 所有已平仓交易净 PnL 之和应等于账户已实现 PnL。
- 回撤值应处于合理范围，且权益创新高时水下值归零。
- 按分组归因的 PnL 汇总应等于总体 PnL。
- 期末权益应等于现金加持仓市值。

## 8. 报告与兼容性迁移

1. 首先扩展结构化结果，保留旧字段。
2. 控制台报告迁移到新字段，并正确显示 `N/A` 及原因。
3. JSON 报告增加 `schema_version`。
4. 更新文档和示例输出。
5. 所有调用方迁移完成后，才移除废弃字段，并在变更日志中说明。

报告至少分为以下区域：

- 回测配置与数据范围。
- 收益与年化指标。
- 回撤和风险。
- 交易质量。
- 暴露和资金效率。
- 成本与执行。
- 策略/标的归因。
- 稳健性与基准比较。
- 数据质量、未建模项和警告。

## 9. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 指标口径改变导致历史结果变化 | 用户误认为策略退化 | 保存新旧对照、公式版本和变更说明 |
| 交易账本不完整 | 所有交易类指标失真 | BM0 优先补齐交易字段与资金对账 |
| 时间频率推断错误 | 年化指标严重偏差 | 优先显式配置，推断失败时拒绝静默计算 |
| 小样本产生夸张指标 | 误判策略有效 | 展示样本量、置信区间和警告 |
| 成本模型不真实 | 高估可实现收益 | 分离已建模和未建模成本，提供敏感性情景 |
| 一次加入太多指标 | 难以定位回归 | 按 BM0–BM6 分阶段、小批量提交和验收 |

## 12. 阶段验收输出

每个阶段完成后应保留下列产物：

- 代码与自动化测试。
- 指标定义文档及公式版本。
- 固定数据集的结构化回测结果。
- 与上一版本的差异报告。
- 已知限制和未建模项列表。
- 更新后的 roadmap 勾选状态。

最终验收不以某次回测“胜率更高”作为标准，而以同一输入下结果正确、稳定、可解释、可复现和可对账作为标准。
