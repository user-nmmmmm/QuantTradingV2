> 文档状态：Active v1.0
> 生效日期：2026-08-23
> 上位路线图：[`unified_roadmap.md`](unified_roadmap.md)（R0–R8，基础设施与放行门槛）

## 1. 范围与边界

`unified_roadmap.md` 管的是**系统可靠性**（账本、事件管线、实盘放行）。
本文件管的是**策略能力**：回测能不能支撑决策 → 选币能不能取代手动指定 →
仓位/保证金能不能支撑合约 → 合约策略本身。两条线共用同一套验收基建
（fixtures、回归基线、诊断模块），冲突时以 `unified_roadmap.md` 为准。

**本文件不承诺盈利能力**。它承诺的是：每个阶段结束时，我们能用可信的证据
判断某个策略/参数/币种是否有效——判断结论是"无效"同样算达成。

### 2.2 关键事实：当前策略组合不具备可用 edge

在 BTC/ETH/LTC/XRP/ADA/SOL 六标的、2017-08-17～2026-06-30 真实 CCXT 日线上：

```
总收益     +74.4%      基准（等权买入持有） +711.9%      超额 -637.5%
Profit Factor 1.29     95% 置信区间 [0.927, 1.767]  ← 下界跨 1.0
最赚钱 10 笔（共 329 笔）贡献 128.6% 净利润  ← 剔除后净亏损
逐年     10 年中 4 年为负；2021 一年贡献 55% 利润
```

结论：**统计上无法排除"这套策略其实不赚钱"**。任何基于当前策略的参数优化都是
在噪声上做文章——这是 S0/S1 必须先于 S2 完成的根本原因。

> 数据边界：Binance 现货最早数据为 2017-08-17，`--start 2016-01-01` 会被静默截断；
> 多标的按时间戳交集对齐，SOL 仅 2150 根 K 线。

## 3. 优先级

沿用 `unified_roadmap.md` 的 P0–P3 定义，本文件补充策略域判据：

| 优先级 | 本域含义 |
| --- | --- |
| P0 | 让回测结论失真或让风控静默失效 |
| P1 | 阻塞下一阶段（如 S2 依赖的账本/诊断能力） |
| P2 | 研究效率与可解释性 |
| P3 | 能力扩展（新指标、新策略族） |

## 4. 阶段总览与依赖

```text
S0 策略层缺陷清理（P0/P1）
 └─> S1 回测收尾（可信度与研究工具）
      ├─> S2 选币模块  ─┐
      └─> S3 仓位与保证金 ─┴─> S4 合约策略
```

- **S0 必须最先做**：D-01/D-02 位于 `strategies/base.py` 与 `router/`，
  选币模块会复用同一套 `on_bar`/生命周期，不修等于把坑带进 S2。
- **S2 与 S3 可并行**：选币解决"买什么"，仓位/保证金解决"买多少、怎么扛"，
  二者接口耦合点只有"目标权重 → 下单数量"这一层。
- **S4 依赖 S3**：没有保证金与资金费率建模，合约策略回测必然虚高。

| 阶段 | 名称 | 退出条件（一句话） |
| --- | --- | --- |
| S0 | 策略层缺陷清理 | 诊断模块不再报 `inert_exit_logic` 与 `blind_strategies` |
| S1 | 回测收尾 | 能对任一策略给出"有效/无效/样本不足"的可复现结论 |
| S2 | 选币模块 | `--symbols` 从必填降级为可选覆盖项 |
| S3 | 仓位与保证金 | 做空成本不再是 `not_modeled` |
| S4 | 合约策略 | 至少一个策略通过 §9 准入标准 |

## 5. S0 策略层缺陷清理

### S0-1 修复出场链路（D-01 + D-02）P0

**问题本质**：策略的出场规则被 Router 的 regime 切换抢先执行，且策略收不到
自己仓位被平掉的事件，导致 (a) 出场参数无效 (b) 依赖平仓回调的风控全部失效。

任务：
1. `_consume_execution_trades` 识别**任何**使该标的归零的平仓成交，
   不再按 `strategy_id == self.name` 过滤掉 Router/CircuitBreaker 的强平；
2. 仓位归零时保证 `on_trade_closed` 必被调用一次（当前依赖策略恰好被再次路由）；
3. 决定 Router 强平与策略自身出场的**优先级契约**并写入
   `backtest_assumptions.md`——是"regime 切换即平仓"还是"策略先出场、超时才强平"；
4. `health_stats` 改为按标的分组，或明确记录"跨标的混合计数"的语义。

验收：`lifecycle_coverage.overall_coverage == 1.0`；`inert_exit_logic` 为空；
构造连亏 6 次样本断言熄火闸门触发。

### S0-2 修复 `optimize.py`（D-03）P1

任务：策略字典键名与 `params.yaml` 的 `routing` 对齐；新增测试断言
"optimize 构造的策略集合能被 Router 全部解析"（现有
`test_strategy_routing_consistency.py` 只覆盖注册表，覆盖不到此处）。

验收：网格搜索产出的交易数 > 0，且不同参数产生不同结果。

### S0-3 执行账本读取复杂度（D-04）P1

任务：`_consume_execution_trades` 改为增量消费（记录游标而非全量重扫）；
`_processed_trade_keys` 加上限或随 context 清理。

验收：遍历次数与成交条数同阶；六标的九年回测耗时不高于当前。

### S0-4 清理与闩锁（D-05/D-06/D-07）P2

任务：删除不可达代码与未使用 import；`entry_pending` 在订单取消/拒绝时释放；
决定 `trend_following.py` 去留（删除，或接回注册表并纳入路由）。

验收：ruff 全绿；构造"订单被取消"样本断言该标的后续仍可入场。

## 7. S2 选币模块

### 7.1 定位

**这是回到项目最初的设计。** 第一次提交（`2937707`）的 `Trading_V1_Model.py`
是一个 BigQuant 横截面排序轮动模型（持有 Top-N、等权、定期换仓），
后来被单标的技术策略取代并移入 `archive/`。S2 是把这条主线接回当前架构。

**为什么值得优先于"换一套技术指标"**：当前单标的择时在 9 年里赚 74%，
而等权买入持有赚 712%。换成另一套单标的指标（RSI/MACD/Supertrend）大概率
是同一个结局——真正的杠杆在横截面选择，而非单标的择时。

### 7.2 任务

| ID | 任务 | 要点 |
| --- | --- | --- |
| S2-1 | Universe 定义 | 交易所 + 计价币 + 最小上市天数；**必须处理退市/下架币种**，否则存活者偏差会系统性高估收益 |
| S2-2 | 流动性与可交易性过滤 | 成交额下限、价格精度、最小下单量；与 `liquidity_limit_pct` 口径统一 |
| S2-3 | 因子计算与横截面标准化 | 按 bar 对全 universe 计算因子并做截面 rank/zscore；**严格禁止未来函数**（复用 `test_no_lookahead.py` 模式） |
| S2-4 | 打分与选币 | Top-N / 阈值 / 分层；输出目标权重而非直接下单 |
| S2-5 | 换仓与换手控制 | 换仓频率、最大换手率、缓冲区（避免边界抖动导致高频换仓） |
| S2-6 | 与执行层对接 | 目标权重 → 下单数量，复用 `clamp_entry_qty` |
| S2-7 | 选币器专用回测指标 | 分层收益（IC/IR、分位组合）、换手率、覆盖度、因子衰减 |

### 7.3 验收

- `--symbols` 从必填降为可选覆盖项，默认由选币器决定
- 分层回测显示 Top 组与 Bottom 组有稳定分离（不只看 Top 组绝对收益）
- 诊断模块对选币结果同样适用：集中度、逐年、连亏不出现红旗
- 存活者偏差已处理并在 `backtest_assumptions.md` 记录口径

> 风险提示：横截面策略对**数据质量**远比单标的敏感。S2 开始前必须先确认
> 数据源能提供退市币种的历史数据，否则整个阶段的结论不可信。

## 9. S4 合约策略与策略准入标准

### 9.1 策略准入标准（Gate）

鉴于 §2.2 的教训，**任何新策略（含 S2 选币器、S4 合约策略）进入组合前必须通过**：

| 判据 | 门槛 |
| --- | --- |
| 样本量 | 闭合交易 ≥ 100 笔（低于此只输出"样本不足"） |
| Profit Factor | 95% 置信区间**下界 > 1.0** |
| 盈亏集中度 | 剔除最赚钱 10 笔后仍为正 |
| 出场健康度 | `own_exit_ratio ≥ 0.5`（出场由策略逻辑而非外部强平主导） |
| 生命周期 | `lifecycle_coverage == 1.0` |
| 样本外 | OOS 与 IS 同向，且 OOS PF > 1.0 |
| 基准 | 对等权买入持有有正超额，或有明确的低相关性理由 |

未通过 = 不进组合。允许结论是"该策略无效"。

### 9.3 存量策略去留决策（S1 期间完成）

数据已足够支撑决策，需明确处理：

- **`RangeMeanReversion`**：两次独立测量 PF 0.33 / 0.43，均远低于 1 → **建议移除**
- **`TrendBreakdown`**：胜率 28.4%，PF 0.48；但样本期是结构性牛市，
  需**牛熊分段验证**后再决定，不能只看全样本
- **`TrendBreakout`**：PF 3.42，是当前唯一利润来源；但出场逻辑失效（D-01），
  修复后需重测——现在的 3.42 未必是它自身逻辑的功劳
- **`VolatilityReversion`**：PF 1.24，修复状态机后表现改善，保留观察

## 10. 明确不做的事

- 账本与诊断稳定前不引入 ML / 新闻 / 链上因子
- 无 tick/盘口数据时不建模真实冲击与订单簿深度（只做参与率近似）
- 不做未经样本外验证的策略扩张
- 不在 `unified_roadmap.md` 的 R7 完成前接入真实资金

## 11. 建议执行顺序

```text
M1  S0-1 → S0-2 → S0-3 → S0-4        出场链路与工具链恢复可信
M2  S1-3 → S1-1 → S1-2               样本外接线 + 术语 + 研究图表
M3  §9.3 存量策略去留决策             用修复后的口径重测并裁剪
M4  S1-5 → S2-1..S2-7                缓存先行，再做选币模块
M5  S3-1..S3-6                        保证金与仓位（可与 M4 并行）
M6  S4                                合约策略，逐个过 §9.1 准入
```

每个里程碑之间产出一次**固定样本差异报告**：记录修复前后指标变化，
防止"修对了但结果变了"被误读为回退（S0-1 必然改变交易结果）。
