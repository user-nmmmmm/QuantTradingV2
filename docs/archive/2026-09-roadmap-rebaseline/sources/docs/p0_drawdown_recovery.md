# P0：组合冻结恢复契约与回测验收

日期：2026-09-05。范围仅为本轮架构审查中的组合 `BLOCK_NEW` 永久冻结问题，
不是宣称项目所有历史 P0、策略重新准入或实盘放行任务已经完成。

**后续更正**：继续排查发现旧止损跨仓位残留，已修复。本文数字保留为当时版本的历史证据，
不再代表当前代码绩效；最新结果与根因见 [`strategy_health_lock_investigation.md`](strategy_health_lock_investigation.md)。

## 1. 根因与修复边界

旧逻辑中，组合权益相对历史高水位回撤达到 15% 后进入永久 `BLOCK_NEW`。
已有仓位退出后，现金权益无法自行回到高水位，于是长期没有重新交易的机会。
实盘此前只持久化熔断布尔值，没有保留组合高水位、动作级别或恢复进度。

本次不删除熔断器，不重置高水位，不绕过策略健康、行情健康、订单未知状态、
保证金、保护性止损和仓位预算限制。独立 PositionManager、选币器和合约实盘不在本次范围内。

## 2. 已实现的行为

| 状态/条件 | 行为 |
| --- | --- |
| 组合回撤达到 10% | 原有 REDUCE；常规定仓风险乘数 0.5 |
| 组合回撤达到 15% | BLOCK_NEW；禁止新开仓，允许已有仓位退出管理；记录 UTC 冷静期截止时间 |
| 冷静期满 30 天 | 系统健康且无日内熔断时，进入组合试运行；风险乘数 0.25 |
| 试运行权益比启动权益再亏至少 3% | 再次 BLOCK_NEW，重新计算 30 天冷静期 |
| 试运行期间原高水位回撤低于 10% | 退出试运行，回到 REDUCE 的 0.5 风险乘数；不自动升为 NORMAL |
| 原高水位回撤达到 20% / 25% | LIQUIDATE / LOCKED 优先，不能通过冷静期自动解除 |
| 当日亏损触发 5% 限制 | 保持独立日内熔断，不因组合恢复而清除 |

组合试运行的 0.25 是基础风险的倍率，不是允许账户亏损 25%。当前基础单笔风险
为 2%，因此该环节给出的名义风险预算是权益的 0.5%；若策略自身处于试运行，
或其他预算/流动性限制生效，还可能进一步降低。成交跳空并不保证实际损失不超预算。

恢复参数在首次历史对照前固定，没有根据本次收益结果搜索或优化。
未提供恢复配置的直接 `RiskManager()` 仍默认关闭自动恢复；项目配置明确启用。
禁止因“恢复成功”额外执行一次减半仓位动作；恢复和降风险事件使用不同的审计 ID。

实盘保留原有日内/终态停机执行路径；本次验证的新增执行能力是 BLOCK_NEW 下
继续退出管理。不能据此宣称实盘已完成与回测完全等价的自动强平执行验收。

## 3. 持久化与兼容性

- SQLite 的 `portfolio_breaker_checkpoint` 保存高水位、动作、日内状态、冷静期截止、
  试运行起始权益、恢复次数、epoch 和动作 ID；风险评估后、策略下单前写入。
- 重启在策略工作前恢复 checkpoint。跨日仅清除日内状态，同时保存新 checkpoint，
  不清除组合冷静期或试运行进度。
- `live_status.json` 导出同一组合状态；状态转移强制落盘，不等待周期性刷新。
- 无时间戳不能自动判定冷静期结束；有效 BLOCK_NEW checkpoint 缺少截止时间时，
  从首次带时间的评估起等待完整冷静期。
- 非法 checkpoint 不静默当作正常状态；零/负权益请求终态保护，而非跳过风险处理。
- 旧版本只有布尔值的数据库不能凭空恢复历史高水位。保留其同日熔断兼容逻辑，
  **不自动推测或重建旧账户组合状态**；真实存量账户升级前需从权威账务核对并迁移。
- 将 `drawdown.recovery.enabled` 设为 false 可停止自动恢复；不要删除状态数据库或降低
  高水位来解除熔断。终态恢复仍需要具名人工审批。

## 4. 历史 A/B 实验

共同输入：30 个币种、日线、2017-08-17 至 2026-06-30、初始权益 10,000 USDT、
seed=42、spot_margin、相同成本与执行配置。输入来自旧报告的 `data_inputs`，
每个文件在加载前校验 SHA-256；不联网、不重新下载行情。

原始来源：`reports/20260902_211518_3239d_30Syms_Ret137.0pct/run_manifest.json`。
它的配置记录明确显示 `strategy_health.enabled=false`，不能把该旧报告与当前默认
配置直接比较而把全部差异归因于本次修复。

## 5. 复现与验收产物

最终完整测试：**632 passed、1 skipped、46 subtests passed**。
上述四个实验臂均已在独立重跑中通过摘要一致性校验，所有组会计对账 `ok=true`。

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/run_p0_recovery_backtest.py
.\.venv\Scripts\python.exe scripts/run_p0_recovery_backtest.py --isolate-portfolio-breaker
```

脚本默认建立新的时间戳目录，绝不覆盖已有实验。使用 `--output` 可指定一个不存在的
目录；使用 `--verify-reference <已有实验目录>` 可以强制比对两组的交易、权益、基准
和报告 payload 摘要。任一摘要不一致或会计对账失败，实验以失败退出。

最终验收目录：

- `outputs/p0_recovery/final_current_config/`：当前配置 A/B。
- `outputs/p0_recovery/final_isolated_breaker/`：组合熔断隔离 A/B。

每组保存完整配置、指标、权益曲线、成交、熔断审计、策略健康转移、风险预算对账、
执行成本审计、融资流水、会计检查、终态以及结果摘要；实验清单保存数据和 Python
源文件哈希。`replay_verification.json` 是针对首次运行的独立重跑校验。

这是已有历史样本上的工程回归，不是新的独立 holdout；不得用于解除
`paused_revalidation`，不得直接用于真实资金放行。没有修改运行中账户、下单或清理旧 Reports。
