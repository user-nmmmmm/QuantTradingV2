# QuantTrading 架构问题与性能优化 Roadmap

核对日期为 2026-10-02。本文记录本次架构复核、性能测量及改进计划，配合现有统一 Roadmap 使用，不改变策略研究结论或真实资金准入状态。用户要求完成余项后的验收记录见 [后续修复与回测报告](architecture_performance_followup_20261002.md)。

本次目标是确认实际交易链路中的逻辑缺陷，建立可复现的回测与行情性能基线，再提高受限速约束的行情并发和调度效率。行情速度同时覆盖数据链路延迟与价格变化速度。

## 当前事实与复现

初始源码为 `b7e6913`，分支为 `codex/p2-p3-signal-meta-layer`，本次开始时 Git 工作树干净。运行环境为 Windows 11、CPython 3.13.2、pandas 2.3.3、NumPy 2.4.2、CCXT 4.5.35，系统报告 16 个逻辑 CPU。

离线最小复现位于 `outputs/performance_20261002/audit_probe.py`，原始结果为同目录的 `audit_before.json`。该目录属于本次生成的实验产物。

## 实施顺序

1. 冻结初始源码与离线基准，验证现有关键测试，保存缺陷复现。
2. 修复 AP01 至 AP05，先恢复行情与决策的正确性。
3. 实施 AP06、AP07，添加覆盖限速、部分失败、确定性提交和调度周期的回归。
4. 完成 AP08、AP09，按同输入成对基准给出实际提升，报告 API 可达性与采样限制。
5. 优先处理 AP11 的总耗时预算与保护单调度，再完成 AP10 的有界追赶、WebSocket 重连及缺口处理；按 AP12 单独测量订单确认链路，并依 AP13 核对混合负载的部署预算。

## 性能指标与验收

回测测量仅覆盖 `BacktestEngine.run`，不含输入生成或报告渲染；验证交易、权益、成本和事件语义一致。行情基准分别记录抓取与本地计算开销，合成延迟只用于容量比较，不作为真实交易所延迟。

实盘链路要区分请求耗时、闭合 K 线年龄、本地决策至模拟订单提交耗时和真实交易所确认耗时。本轮只调用公开行情接口；交易所私有订单确认速度需要独立沙盒或真实运行证据。

价格速度使用相邻收盘价对数收益除以实际经过的分钟数，单位为 bps/分钟。记录绝对速度的中位数和 p95，另外报告每根 K 线高低区间；这些都是已观测样本的统计，不是未来价格预测或逐笔速度。
