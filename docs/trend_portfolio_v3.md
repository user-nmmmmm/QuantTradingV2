# TrendPortfolioV3：全市场日线组合研究

本版本是 V2 的独立后继研究，默认不启用。主程序、正式路由和真实资金准入不因研究代码存在而改变。
工程结果、行情覆盖、历史成员证据、融资证据和策略成绩分别验收；原 V2 报告保留。

## 冻结研究定义

- 市场：从 Binance 官方历史月/日归档分页发现全部 USDT 现货市场，保留退市市场。只做多，账户最大杠杆 3；子簇 1.5、加密总敞口 2 等更严格限制继续生效。
- 评价：2020-01-01—2026-09-18，2019 起准备预热，初始资金 10,000 USDT。所有历史均为回顾性研究，未打开旧前瞻协议。
- 资格：来源支持的非稳定币/非法币/非杠杆代币，上币至少 180 天，至少 121 个连续完整收盘价，20 日真实报价币成交额中位数不少于 500 万 USDT。未知分类/上市知识时间明确拒绝。
- 信号：60/120 日简单收益等权均值为正且收盘高于 SMA120。动量版直接参与周目标；突破版新增风险还需此前20日高点突破与原 OBV 净累积确认。已有仓位不要求重复突破。
- 选币没有 TopN；所有达标币获得目标，执行限制导致的未完成目标必须保留原因。相对权重为逆60日波动率；组合协方差采用样本估计、365日年化、20%向对角收缩，约束前波动目标10%。不使用矩阵求逆，不因资产数超过样本数而删除资产。
- 周一 UTC 用已完成日线冻结数量/风险；每日核对并推进剩余目标。普通偏差容忍10%，零目标退出例外。普通买卖双边成交加在途承诺合计受周一冻结权益50%约束；强制退出单列。
- 单币权重最多30%，新增单币初始风险1%，父簇初始风险3%，单日新增风险2%。账户和健康风险倍率只应用一次；目标被削减后不重新分配剩余资金。
- 初始2 ATR、追踪2.5 ATR、动量转负或60日低点退出；365天安全退出独立归因。止损/风险退出撤销本周剩余买入批准，不能从旧目标重新补回。

## 数据与接口

`core.selection_v2` 提供独立 `all_qualified` 接口；S2 v1 的 TopN/现金契约不变。
`core.margin_rebalance` 规划受账户批准额度约束的订单；`core.portfolio_target_controller` 在共享运行内核中协调
目标、持仓、挂单、保护单和已消耗预算。它默认关闭，通过研究 runner 显式注入。

采集目录保存原始响应字节、校验文件、分页信息、每市场CSV和清单。CSV包含基础币 volume 和实际 quote_volume，
不能用 close×volume 冒充原报价币成交额。归档首末行不是上市/退市公告；公告发布时间、生效时间和抓取时间分别保存。
时间戳兼容毫秒/微秒，信号只接收完整且已可得的日线。成员按信息可得时间处理，不使用全样本最后一行预知退市。
缺少当时可核验的订单过滤器时，最低名义额5 USDT、数量步长1e-8作为登记模型假设；不把默认参数声称为完整历史交易所规则。

融资研究 `assumed` 缺证据部分按明确登记的资格/额度假设和年化8%估计，并测试16%/24%；
`verified_only` 缺资格、额度或利率时禁止新增债务。账户USDT利率独立于币种顺序，实际成交再次检查借款额度。
可以在数据目录提供 `quote_borrow_facts.json` 数组：account（回测为backtest）、quote_currency（USDT）、
effective_at、available_at、annual_rate、limit、status、source_uri、可选expires_at。该文件纳入研究身份哈希。
签名接口凭证及真实账户操作不在数据采集入口中使用。

期末 `valuation_only` 只报告未平仓估值与待处理订单，不伪造成交或平仓样本。
无当前真实行情的持仓标记陈旧，报告其零回收压力；已知停止交易的市场不能继续使用缓存行情撮合。
纯日线不能确定已知日内停止交易前的实际流动性，相应执行区间保守拒绝。

## 执行与恢复

```powershell
.\.venv\Scripts\python.exe -m scripts.collect_trend_portfolio_v3_data --help
.\.venv\Scripts\python.exe -m scripts.run_trend_portfolio_v3 --bundle reports/trend_portfolio_v3_20260921/market_data --output reports/trend_portfolio_v3_20260921/study --register-only
.\.venv\Scripts\python.exe -m scripts.run_trend_portfolio_v3 --bundle reports/trend_portfolio_v3_20260921/market_data --output reports/trend_portfolio_v3_20260921/study --resume
```

采集按内容哈希复用成功响应，失败保留原因并受服务器限流退避约束。仍在变化的数据不能注册研究。
注册保存代码、配置、数据、完整尝试矩阵和源码快照；包括路由、因子和所有新控制模块。
恢复校验冻结身份及已完成产物哈希；失败运行保留原目录，修复代码后必须建立新的研究身份，不能覆盖旧失败。
单独运行某个已登记任务可用 `--resume --only <run_id>`，适合独立进程调度；不能用线程并发改写配置单例。
完整矩阵也支持 `--resume --workers 4`；先执行V2对照，然后使用独立进程。主台账记录排队/完成/失败，各运行目录的
`attempt_started.json`记录实际开始时间。研究仅计算协议中的BTC/ETH风险匹配基准，跳过未使用的全市场日频等权基准。

固定矩阵88次：两策略×两融资口径的主运行、13完整半年、近期、1.5/2倍成本及四个单因素邻域，
另加两策略的16%/24%假设利率压力。V2-C/D原始及显式健康政策对照另4次；D原本满足三币门槛，其对应项是身份对照。
邻域仅40/80、80/160收益周期和300万/1000万成交额门槛。禁止按结果追加搜索或替换主方案。

## 验收与产物

工程测试覆盖未来扰动、无限数量、协方差、真实Broker部分成交、资金与风险共用、实际融资、保护、
周度目标、取消恢复和无伪造期末成交。运行器输出配置、权益、成交、融资账本、健康状态、目标执行审计及来源身份。

研究主候选要求净收益与风险匹配BTC/ETH买持超额为正、最大净权益回撤≤15%、至少30个退出日cohort、
至少2/3完整半年盈利、PF分块置信下界>1、去最优1/3/5/10组、近期和成本压力及固定邻域门槛。
PF采用块长5、2000次重采样、固定种子42。真实融资若尚未权威分配给平仓cohort，PF保持执行成本后诊断并标记
融资完整性不足，不能因为账户权益扣了利息就冒称每组PF也扣了全部融资。

`REPORT.md`、`results.csv`、`acceptance.json` 分别给出工程、数据和策略结果；完整市场成员或历史版本证据不足
会保持 `insufficient`。即使完整归档下载成功，也不自动等于完整历史可交易成员已核验。15%为研究淘汰线，不保证实盘损失上限。
