# 仓位管理模块实施边界（PM）

状态：设计草案，2026-09-05；不是已经上线的模块。依据本轮
[`策略锁定排查`](strategy_health_lock_investigation.md) 和已有共享 EventProcessor、Portfolio、
ProtectiveOrderManager、RiskManager 设计。项目准入仍服从统一路线图与当前策略专项。

## 1. 要解决的具体问题

当前已有仓位管理能力，但所有权分散：Router 分派已有仓位退出；策略维护 stop/context；
保护单管理器按 symbol 保存棘轮；RiskManager 给出组合风险状态；回测/实盘适配器执行动作。
本次旧止损残留说明：symbol 不是足够的生命周期标识，新仓位不能继承上一仓位的状态。

PositionManager 不创建第二本资金账，不替代 Portfolio，不自行生成 Alpha，也不绕过
健康门控。它只把“当前仓位事实 + 各层约束”合成明确、可审计的持仓管理决策。

## 2. 输入、输出和职责

| 边界 | 契约 |
| --- | --- |
| 仓位身份 | account + symbol + side + position_id/epoch；未对账身份不得按旧 symbol 状态继续 |
| 权威输入 | PortfolioSnapshot、订单/成交事实、仓位 lots、保护单事实、策略退出意图、组合风险决策 |
| 输出 | HOLD、REDUCE_TO、CLOSE、ENSURE_STOP，以及是否允许新增风险；附原因和决策 ID |
| 执行 | 交给现有 ExecutionPort；未知订单先查询/对账，不盲目重下 |
| 持久化 | 决策与目标仓位绑定；重启重放幂等，不因重复 tick 再减一次 |
| 清理 | 确认 flat 后注销旧 context、棘轮与残留订单；新 position ID 使用新的初始止损 |

建议调用关系：

```text
仓位/订单/成交权威事实 + 策略退出意图 + 组合风险约束
                         ↓
             PositionManager：合成一次决策
                         ↓
             ExecutionPort：执行/查询/对账
                         ↓
               回填成交事实与审计证据
```

健康 COOLDOWN/MANUAL_LOCK 禁止开仓，不禁止退出和保护单维护。组合 20%/25%
终态与未知订单保护不得由仓位模块擅自解除。策略恢复后也不能放松同一仓位的有效止损。

## 3. 分批交付与验收

| 批次 | 范围 | 验收 | 状态 |
| --- | --- | --- | --- |
| PM0 | 修复已确认空仓后的旧止损残留 | 立即重入、空仓多日、实盘对账；保留部分仓位保护 | 本轮完成，未创建新模块 |
| PM1 | position ID/epoch 绑定、共享持仓管理决策 | flat→new、long→short、人工交易与重启边界；不改变策略收益逻辑 | 待开发 |
| PM2 | 组合目标风险、减仓动作幂等、预算预留 | 部分成交、撤单、超时/UNKNOWN、减仓与止损冲突只执行一次 | 待开发 |
| PM3 | 健康裁决快照与 shadow 观察 | 裁决时 cohort ID/R 固定，锁定后平仓不改写当时证据；shadow 零真实订单 | 待开发 |
| PM4 | 执行一致性和运行准入 | 回测/回放/sandbox 故障矩阵、会计对账、paper 观察 | 待验收 |

PM1 应先做行为保持的抽取，复用现有组件，再增加跨快照重开/反转能力。
不要在同一批次同时改入场策略、健康阈值、杠杆和合约模式，否则无法判断差异来源。

## 4. 健康门控后续研究

当前“3 cohort 总 R > 0、连续两轮失败则 MANUAL_LOCK”仅是已有研究候选参数。
本轮确认修复后的最后三个退出批次确实亏损，但这不证明三个批次足够判断 Alpha 永久失效。
后续可按已有注册表研究样本数、观察窗口与成本敏感性；不要根据此次历史锁定日期反向选参。

在人工锁定后，优先用独立 shadow 账本收集恢复证据，不将 shadow 成交写入真实账本，
不自动清除 MANUAL_LOCK。任何改变恢复权限的上线方案需另行确认，并通过独立样本外准入。

选币器后续输出候选和目标权重，仓位模块负责将其变成受约束的目标仓位；合约接入还需要
保证金、资金费率、持仓方向、reduce-only 与强平语义验收，不能因 PM1 完成直接上线合约。
