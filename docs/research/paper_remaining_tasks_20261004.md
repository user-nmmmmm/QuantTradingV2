## 1. 执行证据和实际工程问题

`scripts/audit_execution_readiness.py` 只读本地记录，不打开交易连接。账本文件名不能证明环境：没有绑定运行身份的旧库保持环境未知。拒单、模拟成交、沙盒成交、合成累计成交和缺证据记录不会变成真实成本样本。成交方向与金额档按已请求的订单名义金额统计，不用市场成交额代替订单规模。

日期资格要求证据在当时已经成熟：报价必须事前可得且新鲜，提交与确认必须属于同一订单，成交和费用需要本地首次观察时间及原始费用证明。明确证明的零费用与数据库默认零不同。跨午夜成交不能因为订单在前一天提交，就提前算成成熟训练证据。最终真实成本拟合与容量验证仍需单独通过，不由“样本计数够了”自动批准。

`scripts/collect_execution_depth.py` 使用 Binance 官方快照与增量深度的序号同步规则，保留事件时间、本地接收时间、可用时间、序号与原始数据。出现缺序会丢弃当前盘口并重新同步；未同步的 REST 快照不被赋予虚构交易所事件时间。盘口计算仅表示所见报价和有限档位的静态扫单诊断，尚未验证挂单撤销、排队、实际延迟和订单冲击。

本轮真实采样暴露了两个问题：REST 原始 `lastUpdateId` 可能以数字字符串返回，已规范化后验证；交易所事件时间与本机接收墙钟出现明显冲突。第二批 30 秒取得 548 个序号同步盘口，但全部被排除为时钟冲突。公开 `serverTime` 对照的低延迟请求给出交易所减本机时间区间 **30.979582–31.095188 秒**。程序保留原始时钟并单列时钟质量，冲突记录不能进入合格成本样本。

只读系统检查发现 `W32Time` 为 `Stopped / Manual`。用户随后明确授权启动服务并同步一次；普通启动因权限不足失败，正常 Windows 管理员确认又返回“操作已被用户取消”，同步脚本没有启动，系统时钟没有调整。这是操作系统管理员确认未完成，不能表述成时间已经修复。已授权操作的固定脚本保存在 `tmp/synchronize_clock_20261004.ps1`，尝试证据在 `reports/paper_remaining_20261004/windows_time_sync.json`；后续真实复核批次与原始冲突批次分开保存。

下一步验收顺序是：确认采集主机时钟及其误差范围，取得具备完整费用和观察时间的真实成交证据，再按冻结的日期与分层规则累积样本，最后在后续日期检验模型误差和资金规模边界。真实订单不会由本研究命令自动提交。

## 4. 严格标签、撤销和延迟执行

`TemporalOHLCV.retract(...)` 通过明确 tombstone 追加撤销。版本选择先找截止点可见的最新修订，再判断有效性，不会自动回落到旧值。信号、入场或中间行情撤销会产生不可训练标签；过去截止点仍能复现过去成熟版本，恢复必须是明确的新修订。

`TemporalFinancing` 保存每条成本证据的事件时刻、接收时刻、可用时刻、修订和来源。线性永续资金费要求合约条款、完整结算网格和窗口覆盖证明；借币要求决策时已知的币种、额度和借款比例，以及连续的固定本金 ACT/365F 计息区间、换算价格和明确费用。默认利率不能替代缺失证明。支持多空和负资金费率，其他产品计费规则不能直接套用。

标签消费者独立重算执行价格、数量、费用账和净收益；只修改净收益再重新哈希也不能通过。融资事件或覆盖证明撤销会让后续标签失效；未来修订不改变旧候选 ID 或早期训练结果。融资证据可由 `--temporal-financing-evidence` 传入常规回测，完整输入进入 `temporal_data.json`，重放检查文件与融资内容双重身份，不读取后来变化的外部文件。

这些融资能力是固定名义本金信号诊断。它们没有声称复原真实借贷账户、追加保证金、复利或强平路径。当前真实历史证明缺失的样本仍排除。

`backtest.delayed_execution.replay_delayed_decisions(...)` 接受预先给定的现货买卖市场单决策、实际可用时间和细周期行情，只有可用时间之后的首个实际开盘才可撮合；行情缺失会等待，不虚构开盘。费用与 IOC 部分成交通过现金及持仓核对；普通订单仍使用原有下一根行情规则。该独立诊断不支持盘中限价／止损及融资路径，主引擎非零延迟限制和迟到候选训练禁用保持明确。要进一步放开，需要把细周期撮合、风险事件、融资和标签钟统一接到主引擎，而不只是移动订单时间戳。
