# 候选身份影响说明：C1（去掉 OBV 确认）与 C2（实盘取数 201 根）（2026-11-10）

> 路线图：[策略整改 Roadmap](../strategy_remediation_roadmap_20261110.md) 阶段 C（批次 4）。
> 本文件在改动配置**之前**写入，按路线图第 4.3 节“改变行为的任务：先写候选身份影响说明”。
> 本批次只改代码与配置，**不登记**新候选身份、**不开**新前瞻观察窗、**不改** `strategy_governance`
> （`TrendBreakout` 仍为 `paused_revalidation`）。登记属于阶段 D（批次 5），需仓库所有者确认后进行。

## 1. 改动

| 项 | 改什么 | 依据 | 是否改变回测 | 是否改变实盘 |
| --- | --- | --- | --- | --- |
| C1 | `TrendBreakout` 入场不再要求 OBV 同向（新配置项 `trend_breakout.use_obv: false`） | [SR-ALPHA-004](entry_delay_study_20261110_results.md)：唯一在 train60 与 validation20 都通过的维度 | **是** | 是 |
| C2 | 实盘滚动窗口下限从 100 根改为 201 根原始 K 线（新配置项 `data.live_min_lookback_bars: 201`） | [SR-DATA-001](live_window_study_20261110_results.md)：100 根窗口 1.15% 的 bar 状态与回测不同，200 根已收盘 K 线完全一致；另留 1 根给未收盘 K 线 | 否 | 是（向回测对齐） |

**一次只改一个维度**：C1 是唯一改变策略回测行为的维度。C2 不改变回测，只让实盘读到与回测相同的状态和信号，
是修正实盘与回测的偏差，不是新的策略维度。两项合在同一个新候选里，新候选与现候选在回测上的差别只有 C1。

不做的项：C3（追踪/保本止损输入修正）与 C4（V3 性能与口径）的触发条件没有出现，按路线图不做；
健康政策不改（[SR1-HEALTH-007](health_power_study_20261110_results.md)：h3 未达门槛）；到期退出不改（[SR-EXIT-001](time_exit_rebuy_study_20261110_results.md)）。

## 2. 预期影响（来自已运行的登记研究，不是新的评价）

| 分段 | 基线 收益 % / 回撤 % / 交易 | `obv_off` 收益 % / 回撤 % / 交易 |
| --- | --- | --- |
| train60 | 64.79 / 9.12 / 145 | 72.12 / 7.98 / 142 |
| validation20 | 0.03 / 6.99 / 59 | 0.22 / 6.99 / 61 |

validation20 的改善只有 +0.19 个百分点，证据偏弱。这些数字已用于选择，**不能**再当作新候选的样本外证据。
final20 只能做一次独立评价（SR5，阶段 D2），并且它已被 2026-10-02 与 2026-11-10 的回顾性研究看过，只能作回顾性证据。

## 3. 对候选身份与观察窗的影响

- 冻结范围（`config/frozen_scope.json`）内的 `config/params.yaml`、`composition/factory.py`、`live_trading/engine.py`
  会变化，因此新代码**不是**现候选身份。现候选的前瞻观察窗 **[2026-10-21, 2027-04-19)**（最早成熟 2027-05-09）
  绑定的是已登记的身份，本批次不碰它，也不得用新代码的结果冒充现候选的观察。
- 新候选必须在阶段 D1 用新身份登记，建立**自己的**前瞻观察窗；观察窗从登记日开始计，不追溯。
- 研究里的 OBV 消融（`research.strategy_ablation: no_obv_confirmation`）保留；在新默认下它与默认等价，
  旧研究的结论按各自的登记身份解读，不重算。

## 4. 回退

两个配置项都可以单独改回：`trend_breakout.use_obv: true` 恢复 OBV 确认；`data.live_min_lookback_bars: 100`
恢复旧实盘窗口（A3 预检仍会拒绝不够用的窗口）。回退同样改变身份，需要按协议处理。
