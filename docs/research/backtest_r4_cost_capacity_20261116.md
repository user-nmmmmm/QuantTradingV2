## 1. 问题

1. 收益在更差的成交假设下是否仍在？盈亏平衡的成本倍数是多少？
2. 哪一类成本项最致命：费率、价差、波动率滑点、冲击，还是未成交（TTL 与部分成交）？
3. 资金规模放大后，收益如何衰减？容量曲线的拐点在哪里？

H0：策略在 2× 联合成本下仍为正，且容量足以承载配置资金。

## 2. 成本方案

引擎中的成本项（`config/params.yaml` 的 `execution` 与费率表，冻结时读取具体键名并写入登记）：
费率（maker/taker）、固定滑点、价差、波动率滑点因子、冲击系数（指数 1.5）、`max_participation_rate`、
`opening_order_ttl_bars`。

| 方案 | 说明 |
| --- | --- |
| `c1.0` | 配置基准（1×），所有成本项原值 |
| `c1.5` / `c2.0` / `c3.0` | **联合**放大：费率、固定滑点（`slippage_bps`）、价差、波动率滑点因子、冲击系数同时乘倍数（与 `current_strategy_protocol.json` 的倍数一致） |
| `fee_x2` / `slip_x2` / `spread_x2` / `vol_x2` / `impact_x2` | **单项**放大 2×，其余不变，用于拆分贡献 |
| `all_taker` | 所有成交按 taker 费率计，检验限价单 maker 假设的贡献 |
| `ttl_{0,5,10,20}` | 开仓单存活期（0 为关闭），默认 10；检验未成交与风险预留锁定的影响 |
| `part_x0.5` | `max_participation_rate` 减半，检验分批成交延迟的影响 |

## 3. 容量方案

初始资金网格：{1e4, 1e5, 1e6, 1e7, 5e7} USDT（含配置的 `capital`，冻结时读取并加入网格）。
其余成本项保持 1× 基准。逐 bar 成交量预算按引擎的 symbol/bar 共享额度规则。
记录：参与率分布（P50/P95/P99）、被拒单与部分成交比例（`execution_audit`）、净夏普与净收益随资金的变化。
日线成交量是全日成交量，不含盘口深度；容量曲线因此是**成交量约束下的上界**，不是盘口可成交量的估计。

## 4. 数据与分段

train60 与 validation20 分别运行；final20 禁止读取。对象：S1、S2（R1 通过的对象才进入判定，其余仅报告）。

## 5. 指标

净收益、`ratio`、夏普、最大回撤、平仓交易数、平均持仓、**成本占毛收益比例**（费用 + 滑点 + 冲击 / 毛盈利）、
被拒/部分成交比例、参与率分位。

- **盈亏平衡倍数**：把联合倍数视为连续变量，对 `c1.0`、`c1.5`、`c2.0`、`c3.0` 的净收益做线性内插；
  若 `c3.0` 仍为正，记为"> 3.0（未触及）"，不外推。
- **半夏普容量**：净夏普降到 1× 参考资金（1e4）净夏普一半时的资金规模，线性内插。

## 6. 预注册判定规则（草案阈值）

对象 X **通过**，当且仅当在 train60 **和** validation20 两段都满足：

1. `accounting_ok` 为真；
2. `c2.0` 联合成本下净收益 > 0，且 `ratio > 0`；
3. 盈亏平衡倍数 ≥ 2.0；
4. 半夏普容量 ≥ 3 × 配置资金（若配置资金不在网格内，使用内插结果）；
5. 在 `all_taker` 下净收益 > 0（不依赖限价单 maker 成交）；
6. 样本量：组合层平仓交易数 ≥ 30。

任一不满足：**未通过**，并在结果里按成本项拆分给出"最致命成本项"（单项放大后净收益降幅最大者）。
不满足 6：**证据不足**。

## 9. 已知局限

- 价差在日线数据里缺失，使用配置默认值；冲击模型的指数与系数是假设，不是对该交易所的校准结果。
  容量结论只能作"在此假设下"的上界。
- `all_taker` 与 maker 假设的差别取决于日线上限价单是否可被触价成交，这在日线粒度下无法验证。
- 真实账户费率须由账户费用证据确认，本研究使用的是回测配置假设（见回测假设第 2 节）。
- 联合放大倍数把五类成本同乘，而真实环境里它们并不同步恶化；单项放大用于补充这一点。
