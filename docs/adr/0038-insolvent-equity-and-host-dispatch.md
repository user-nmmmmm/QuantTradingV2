# ADR 0038：零负权益、catchup 市场别名与宿主 hook 分派

- 日期：2026-10-15。状态：已采纳。
- 范围：AUD-05；基于已合并 #103 的 main `4e3669e57dc3148a017f470c0f0e165eeebcf70a`。

## 问题

dashboard 原先丢弃零负权益观测，使失败实验被展示为最后一个正权益点。直接计算相邻收益率又会除零，或把负资本分母产生的符号变化当作收益。图表、Excel 和附加风险统计使用不同的处理路径。catchup 没有沿用常规抓取对 `swap` / `perpetual` 的客户端映射。报表协作类的分节调用和 Broker 的时间转发绕过了宿主子类保留的 hook。

## 决定

1. dashboard 保留所有有效时间上的有限权益值，包括零、负值及之后的恢复；不修改输入 CSV。第一个有效权益必须为正，不能跳过零负起点后重新选基准。回撤以此前正峰值为分母，允许低于 -100%；无法用有限浮点数表达时明确拒绝。`100 → 120 → 0 → -10` 的最终权益为 -10，总收益 -110%，最大及当前回撤约 -108.33%。
2. 百分比收益要求正的前期权益分母。正基准到零的收益为 -100%，到负值允许小于 -100%；零负基准之后的收益未定义。`equity_period_returns` 保留观察时钟，以缺值标记无效区间，不跨越、不填零。core 指标、月度记录、基准相关性、报表风险统计、图表和 Excel 使用同一口径；dashboard 的无依赖分析实现同一规则。
3. Sharpe 和附加风险统计不能丢掉未定义区间再报告一个较小样本的成功结果：整体返回 undefined，保留原区间数量。月度记录保留未定义月份和原因；图表只绘制定义的收益柱，Excel 留空相应收益单元格，原始权益与回撤继续保留。年化收益只在正起点、非负终点、正时间跨度下定义；零终值为 -100%，负终值为空。指标公式版本升为 `2.1`，旧报告不改写。
4. 常规快照和 catchup 共用客户端类型及缓存键映射：`future`、`futures`、`perpetual`、`swap` 为 `future`，spot/margin 使用 `spot`。保留衍生品 metadata 的 contract 检查，禁止别名悄悄退回现货；请求的标的、时间和原有来源记录不重写。
5. 文本报告的全部 11 个保留分节 hook 通过宿主调用，保留子类的实例/静态覆盖和 `super()` 链。Broker 的 `_iso_time` 通过 `cls._event_time` 格式化，使静态/类方法覆盖进入规范订单时间和订单身份；默认 Broker 的 UTC 序列化保持原行为。

## 验证与后果

回归使用合成权益、临时报告和内存 CCXT 客户端，覆盖清零、负债、恢复、非法起点、月度边界、JSON/cache、实验对比、真实报告/Excel/图表，以及六个市场别名的双向客户端复用、四个衍生别名的现货拒绝、全部分节 hook 和订单事件时间。相关运行回归加入 Ubuntu/Windows × Python 3.11/3.13 安装矩阵；完整质量任务、离线与 ML 测试继续运行。

这些是报告计算、客户端选择和子类扩展行为的修复，改变冻结源码身份。旧指标版本、历史研究记录和登记回执保留原样；后续研究应以新提交重新计算并绑定来源。默认撮合、费用及风险规则不改；不执行真实交易、实际候选登记或数据采用。必要时回退本 PR，并按回退后的源码身份重新形成评估证据。

现有引擎 v4 基线的权益始终为正，继续保留原文件及 `2.0` 版本。等价测试只在内存副本中将预期版本明确改为 `2.1`，其余成交、权益、基准、指标、状态及说明仍逐项比较；不自动接纳其他版本或重新生成基线。零负权益的新语义由独立合成回归固定。
