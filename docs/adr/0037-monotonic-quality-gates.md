# ADR 0037：棘轮更新、共享质量任务与实际隔离约束

- 日期：2026-10-15。状态：已采纳。
- 范围：AUD-04；承接 ADR 0022、0023、0024 和 0026，操作说明见[质量门槛](../quality.md)。

## 问题

棘轮 `check` 拒绝新增问题，但 `update` 原先直接覆盖基线。CI 有 90% 覆盖率与前端测试，本地 `check` 缺少两项，旧一致性测试只核对命令子串。隔离策略按源码标记数量估算，未覆盖参数展开或继承，也没有 30 天上界。容器路径过滤遗漏了安装和质量配置 `pyproject.toml`。

## 决定

1. `check` 与 `update` 共用逐条比较及 mypy 硬门槛。选中工具全部计算、检查通过后才写基线；其他条目的减少不能抵扣任何新增或增长。失败不写文件，`--tool` 保留未选工具，缺失基线视为零额度。现有存量额度和规则不提高。
2. CI 的每个质量步骤调用 `scripts/dev.py` 的对应任务。本地 `check` 与 CI 任务及顺序由双向回归约束。`test` 固定五包行覆盖率至少 90%，缺少 xdist 只允许串行；`frontend` 由 Python 展开并排序所有匹配文件，空集合拒绝，Node 错误正常传播。`sandbox` 复跑保留。安装与条件 PR 身份报告单列；`fast` 供无覆盖率要求的定向调试。
3. `check --no-tests` 继续作为显式短检查，跳过 Python 测试、覆盖率和 sandbox，保留前端测试。容器沿用短检查，完整 Python 验证由 `tests` 工作流负责；不把短检查成功等同完整 CI。
4. pytest 收集钩子先于选择过滤运行，对实际 item 计数：参数化、子目录、类/模块和参数标记均计入，单 item 多标记不重复计数，但逐个验证所有继承标记。最多 10 项；原因去除首尾空白后至少 10 个字符，日期必须为 `YYYY-MM-DD`，位于 UTC 当天到加 30 天内（含边界）。策略错误设置 session 失败原因再终止收集，使 xdist 控制端能收到明确原因并停止调度；验证通过后才加非严格 xfail，保留运行、XFAIL/XPASS 语义。
5. 容器 PR 与 main push 的路径过滤同时包含 `pyproject.toml` 和工作流自身，回归分别验证两个事件。

## 验证与后果

回归覆盖各工具的新增/增长、总数下降但新增单项、混合改善与回退、部分更新、缺失基线、工具失败、硬门槛拒绝及字节不变；真实低覆盖率和 Node 断言失败必须使共享运行器失败。隔离使用临时项目进行真实 pytest 收集，覆盖 10/11 项、0/30/31 天、过期、无效字段、继承遮蔽、多标记、选择过滤和 xdist 全量收集。

完整本地检查现要求 Node.js 22 与 pytest-cov；缺少工具必须显式失败。UTC 日期避免 CI 与开发机时区导致边界分歧，延期仍须在 PR 中说明原因与负责人。没有新增隔离标记、跳过项或质量豁免，不修改真实数据和历史验收记录。

pytest 的[钩子顺序](https://docs.pytest.org/en/stable/how-to/writing_hook_functions.html#hook-function-ordering-call-example)与 xdist 的[完整 worker 收集](https://pytest-xdist.readthedocs.io/en/stable/how-it-works.html)是实现依据；实际执行由回归测试验证。
