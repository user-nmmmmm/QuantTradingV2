# 0042 选币推理使用已校验字节，历史交付身份独立固定

- 状态：已采纳
- 日期：2026-10-17
- 相关：[模型接入](../ml_selection.md)、[文件保留](../file_retention.md)、[身份说明](../identity.md)

## 问题

选币包先验证路径中的文件，随后加载模型、计算包摘要和复制快照时重新读取路径。
如果文件在这些步骤之间变化，推理实际使用的设置可能与回执摘要不同，或报告保存了无法重放的模型副本。
包内的绝对路径即使指向原包内部，也不能构成可移植、自包含的重放快照。

历史交付 ZIP 的清单在没有本地副本时只做宽松字段检查。
删除清单部分、移除单个条目或改写摘要可能仍通过卫生门禁，不能保证这些已迁出的证据继续保留原身份。

## 决定

1. `read_bundle_snapshot` 对包清单和每个模型文件各读取一次，校验实际捕获的字节。
   推理从同一份模型字节构造对象，回执使用同一份清单字节的摘要。
   旧 `read_bundle` 和按路径加载模型的 API 保持可用；字节加载复用相同的版本、内容身份和特征校验。
2. 保存快照前先捕获并验证全部输入，再写入捕获的字节，不在复制阶段重新读取模型源路径。
   包清单已改变时拒绝冒充原候选；已有目标目录继续拒绝覆盖。
3. 包成员采用规范的相对 POSIX 路径，可包含子目录；拒绝绝对路径、驱动器路径、反斜线、父目录跳转、
   重复成员路径及与快照清单冲突的名称。保留名与重复检测不区分大小写,避免 Windows 上的文件覆盖;
   `manifest.json` 也不能被当作模型子目录。解析后的源文件仍须在包目录内。
4. 卫生门禁独立固定三个历史交付物原有的名称、大小、SHA-256、Release URL 和原路径。
   清单负责描述这些事实，不能通过删改自身重新定义它们。拒绝缺失/额外/重复记录及无效字段；
   本地副本可选，但一旦存在就必须是完整且匹配的文件。此门禁不联网，不更改 Release 资产。

## 验证与边界

回归覆盖模型加载期间的清单变化、校验与快照写入之间的源文件变化、可移植路径、
清单删除、身份改写和缺失本地副本的情形。现有模型/CLI/报告重放与默认关闭路径继续测试。
历史交付身份来自迁出前的 Git 对象，并与公开 Release 的大小和 SHA-256 元数据核对。

本次会改变冻结范围中的源码身份，后续发布仍须绑定最终提交并按协议另行登记。
现有模型权重、包清单、市场输入和历史回执不改写；工程修复不启动观察窗口或改变策略准入。
完整补审、治理清单、保留方案和登记资料继续保留本地。
