# 0003 新增行为身份，不改写旧冻结记录

- 状态：已采纳
- 日期：2026-10-11
- 相关：[PR #64](https://github.com/user-nmmmmm/QuantTradingV2/pull/64)，`core/foundation/source_identity.py`，[身份说明](../identity.md)

## 背景
既有的冻结身份对源文件字节做哈希，所以改注释、重排空行、统一换行符都会让身份变化，任何整理代码的改动都被当成"冻结候选的源码变了"。但旧记录里存的是旧方案的哈希，改写会让这些记录失去可验证性，削弱研究完整性控制。

## 决定
- 不改写、不放宽任何旧的校验；旧记录继续按创建时的方案验证。
- 新增第二种身份方案 `code-token/v1`：Python 文件按去掉注释和纯排版 token 后的 token 流哈希，其他文件按字节（文本统一换行符）。字符串内容和 docstring 仍算行为。
- 冻结范围由 `config/frozen_scope.json` 声明；PR 的 CI 摘要给出行为 / 新增 / 删除 / 仅格式的影响报告（提示性，不阻塞）。
- 规范化只依赖分词，f-string 在 3.12 前后的分词差异按原文还原；金标准哈希测试要求 3.11/3.12/3.13 一致。

## 备选方案
- 把旧身份迁移到新方案：会使已存的哈希失效。
- 身份绑定到发布标签 + 证据清单：需要先有发布流程，列为后续。

## 后果
新旧两套身份并存；新方案目前只提供可见性。若将来所有冻结记录都改用新方案，应新增 ADR 取代本条。
