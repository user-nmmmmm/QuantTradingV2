# 0002 用"只减不增"的棘轮管理存量 lint / 类型问题

- 状态：已采纳
- 日期：2026-10-11
- 相关：[PR #65](https://github.com/user-nmmmmm/QuantTradingV2/pull/65)，`scripts/quality_ratchet.py`，[质量门槛](../quality.md)

## 背景
CI 的 ruff 只开语法级规则，mypy 只查 3 个文件，覆盖率门槛 55%（实际 89%）。扩大规则后存量问题很多（ruff 约 620，mypy 约 870，其中 475 个是 mixin 访问宿主属性造成的 `attr-defined`），无法一次清零，一次性修改又会大面积触碰受冻结研究保护的源码。

## 决定
- 按"文件 + 规则"记录当前问题数量作为基线，`check` 只允许减少、不允许增加；修掉问题后用 `update` 锁定改进。
- 保留原有的硬门槛不变；棘轮是额外的一层。
- mypy 固定按 `linux` / Python 3.11 分析，保证开发机与 CI 计数一致。
- 覆盖率门槛提到 85%（实测约 89%），测试并行、600 秒超时、`--strict-markers`。

## 备选方案
- 立即全量启用并修复：改动面过大，风险高。
- `--add-noqa` 批量压制：在数百处插入注释，噪音大且掩盖问题。
- 只对改动文件检查：无法阻止他处回退，也难以复现。

## 后果
基线文件需要随改进更新；mixin 相关的类型错误会随"mixin 改组合"的重构自然消失。可以把清零的规则提升为硬门槛。
