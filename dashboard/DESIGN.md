# Stillwater Quant 前端设计简报

更新：2026-10-04。本文记录设计依据与验收标准；实际接口、启动方式和模块职责以本目录前端开发文档及代码为准。2026-10-03 的参考调研与配色依据继续有效；本轮精修决定见第 10 节。

## 1. 设计命题

面向在本机运行策略的量化开发者，把账户观察、策略回测、行情分析、实验对比、数据质量、稳健性研究和运行排障整理成一个工作台。情绪关键词：**沉静、精确、可追溯**。延续 `web_theme.css` 的绿色 / 青色品牌与浅深双色，不引入外部字体、装饰视频或大型特效库。

核心概念：**像一台研究仪器，先给读数，再给证据，最后给可执行的下一步。** 最明显的设计选择是为回测提供独立工作区，让参数、运行状态和分析结果保持连续上下文。

## 2. 行业调研与证据边界

调研包含 7 个金融 / 回测相关样本，覆盖成熟平台、独立工具和获奖金融品牌。以下来源在本次调研中通过网页文本或搜索索引读取；没有登录付费产品，也没有对外站进行完整浏览器视觉验证。除明确列出的颜色外，外站字体、像素级布局与动画速度均未确认，不作为事实引用。

| 样本 | 层级与出处 | 已确认的决定 | 本项目的取舍 |
| --- | --- | --- | --- |
| [QuantConnect Results](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/results) | 成熟量化平台；官方文档已读取 | 同一结果页包含资金曲线、统计、交易和日志；运行时持续更新 | 回测状态与结果同屏；错误可定位。无需照搬全部指标 |
| [TradingView Strategy Report](https://www.tradingview.com/support/solutions/43000764138-tradingview-strategy-report-how-to-start/) | 成熟图表平台；官方文档已读取 | 指标、绩效、交易分析与交易列表分层；资金曲线可对照买入持有 | 回报、回撤和交易证据分层；保持基准开关明确 |
| [QuantRocket](https://www.quantrocket.com/) | 专业量化工具；官网文本已读取 | 产品工作流覆盖数据、研究、回测、运行监控 | 导航按任务组织；本地启动路径与运行状态可发现 |
| [Backtesting.py](https://kernc.github.io/backtesting.py/) | 独立开源工具；官网文本已读取 | 少量策略参数连接统计输出与可缩放图表 | 参数表单直接驱动结果；指标明确单位与时间区间 |
| [Portfolio Charts Instructions](https://portfoliocharts.com/user-guide/instructions/) | 独立研究工具；读取搜索索引正文，直接打开失败 | 同一投资组合可以切换不同分析问题；输入设置与图表预设有明确关系 | 结果页围绕“收益如何、损失多大、交易如何发生”组织 |
| [Rogo](https://www.awwwards.com/sites/rogo) | Awwwards Honorable Mention，2024-03-28；榜单页已读取 | 金融机构定位，独立展示产品和安全相关内容 | 来源与可信状态有固定位置；其营销页面不等于实际研究终端 |
| [Cash App Brand Guidelines](https://www.awwwards.com/sites/cash-app-brand-guidelines) | Awwwards SOTD，2025-05-17；榜单页已读取 | 榜单记录黑色 / `#00D533` 色板，具有交互与 3D 展示章节 | 借鉴强调色一致性；高饱和绿、开场动画和 3D 不适合本工作台 |

行业刚需是可辨识的数据来源、运行状态、时间范围、策略参数、绩效和交易明细。可以放弃的惯性是满屏同时运行的图表、只有颜色的涨跌表达、指标卡数量不断增加、把运行异常藏在页面底部。

项目定位：**一个保留本地数据上下文、能够解释回测结果的研究工作台。** 这是本项目的设计选择，不是对所有竞品能力的比较结论。

提炼为 5 条原则：

1. 结果旁边保留参数、时间范围和数据来源，参考 QuantConnect、Backtesting.py。
2. 关键绩效 → 曲线与基准 → 交易明细，参考 TradingView。
3. 导航以用户任务分组，当前任务只突出一个主要操作，参考 QuantRocket、Linear。
4. 每张图回答一个明确问题，先说明口径再允许探索，参考 Portfolio Charts。
5. 允许从不同问题进入同一份证据，保持上下文一致，参考 Plenaire 的多路径内容方法。

## 4. 风格家族与信息架构

主家族为技术仪表，辅助采用瑞士网格的对齐纪律。区别于常见技术仪表的冷黑与荧光色，本项目使用低饱和青绿、清晰留白和中文说明；不使用扫描线、闪烁读数或装饰性代码。

| 主导航 | 首要问题 | 主要内容 | 主要操作 |
| --- | --- | --- | --- |
| Overview / 工作台总览 · `#overview` | 当前账户与系统是否正常？ | 资产、敞口、状态、资金曲线、持仓摘要 | 刷新数据 / 进入回测 |
| Backtest Lab / 回测实验室 · `#backtest` | 这个策略在给定历史区间表现如何？ | 数据与策略参数、运行状态、收益与回撤、基准、交易结果与风险诊断 | 运行本地回测 |
| Market Data / 市场行情 · `#market` | 价格、成交量和技术指标如何变化？ | OHLC、成交量、技术指标、数据来源与更新时间 | 切换品种 / 指标 |
| Experiments / 实验与对比 · `#experiments` | 哪些实验值得保留，结果差异在哪里？ | 实验档案、收藏与标签、2–4 份报告的净值 / 回撤 / 参数对比 | 筛选档案 / 比较实验 |
| Data Quality / 数据管理 · `#data` | 当前历史数据是否完整、有效？ | 覆盖区间、重复、缺失、顺序与 OHLCV 检查 | 重新检查 |
| Walk-forward / 稳健性研究 · `#robust` | 参数在样本外是否稳定？ | 滚动训练与测试窗口、研究任务、样本外曲线、参数热力图 | 配置并运行研究 |
| Operations / 运行监控 · `#operations` | 任务、告警和风控哪里需要处理？ | 服务健康、策略状态、检查、活动和告警 | 筛选告警 / 检查状态 |

当前是七个独立任务视图，桌面使用左侧稳定导航、顶部轻量状态栏与主内容区。移动端七个入口保持单行横向滚动，当前项需进入可见区域。导航必须有清楚的当前项；可深链接的页面优先使用链接语义，同页标签切换才使用完整的 tab 键盘模式。切换任务保留合理的表单上下文；浏览器返回能够回到上一任务。

## 5. 配色候选与对比度

推荐保留 A，并继续提供 B 作为深色主题。C 为候选方向，不纳入本轮实现。色值 A / B 直接取自仓库 CSS，未取自竞品。对比度用 WCAG sRGB 相对亮度公式计算，正文和次文字均以各自 `surface` 为背景。

| 角色 / CSS token | A：雾绿浅色（推荐） | B：夜间青绿（已有深色） | C：纸色研究台（候选） |
| --- | --- | --- | --- |
| 页面 `--bg` | `#f2f5f3` | `#101b1f` | `#f5f2e9` |
| 面板 `--surface` | `#ffffff` | `#17272b` | `#fffdf6` |
| 正文 `--ink` | `#1c3438` · **13.14:1** | `#e8f1ed` · **13.39:1** | `#253b35` · **11.75:1** |
| 次文字 `--muted` | `#5b7073` · **5.24:1** | `#a9beb9` · **7.90:1** | `#5b6b61` · **5.55:1** |
| 分割 `--line` | `#dbe5e1` · 1.29:1 | `#30464a` · 1.54:1 | `#d9ded3` · 1.35:1 |
| 强调 `--accent` | `#086e67` · **6.11:1** | `#73d4c0` · **8.75:1** | `#256458` · **6.78:1** |
| 强调上文字 `--accent-ink` | `#ffffff` | `#102e2d` | `#ffffff` |
| 警示 `--warn` | `#956022` · **5.28:1** | `#e8b977` · **8.55:1** | `#895b20` · **5.76:1** |
| 负向 `--bad` | `#ae4d48` · **5.31:1** | `#f09a8f` · **7.14:1** | `#a3473c` · **5.86:1** |

主按钮文字 / 强调背景分别为 A **6.11:1**、B **8.21:1**、C **6.90:1**。次文字 / 页面背景分别为 **4.77:1**、**8.97:1**、**5.04:1**。这些数值仅证明列出的组合，不代表透明层、禁用态、图表和所有状态已经完整通过无障碍测试。

面积比例约 65% 背景与低饱和表面、30% 内容和结构、5% 强调。强调色只用于当前导航、主操作、重点数据系列与焦点；警示色用于确实需要注意的状态。分割线对比度较低，只承担装饰分组，不能作为控件可识别性的唯一依据。当前输入使用专用 `--field-border`：浅色 `#758d89` 与表面对比度 **3.54:1**、深色 `#7a9690` 与表面对比度 **4.84:1**；精修继续保留该角色，不回退成装饰分割线。状态还必须有文字、符号或线型区别。

## 6. 排版与版式

- 正文沿用 `--font-body`：Aptos / Segoe UI / PingFang SC / Microsoft YaHei；数据和标题沿用 `--font-data`：Bahnschrift / Aptos Display；时间、标识和技术值沿用 `--font-mono`：Cascadia Code / SFMono-Regular / Consolas。
- 正文建议 13–14px，字段与次要说明 12px，区块标题 20–22px，页面标题 32–40px，首要读数 36–46px；新增字号应集中到 token。中文说明行高 1.65–1.8，正文不使用英文式宽字距。
- 数字等宽排列，金额和比率右对齐，单位单独标注。空值显示“— / 暂无数据”，不能显示为零收益。百分比、货币、UTC / 本地时间的口径要明确。
- 间距使用现有 4 / 8 / 12 / 16 / 24 / 32 / 48px 刻度。主图占据分析区最大面积；辅助统计使用紧凑行和定义列表，避免新增整排重复卡片。
- 回测页宽屏采用约 300px 参数列 + 弹性结果区；屏幕收窄后参数列移至结果上方。运行完成后仍能回看参数，不把结果替换整个表单。
- 1440px 检查侧栏与双列；1024px 检查主图可读宽度与控件换行；390px 改为单列和紧凑横向导航，触控目标至少 44px。大表格仅在自身容器横向滚动，页面整体不溢出。

## 7. 组件、质感与图表

细线和表面明度差是唯一主要质感。面板沿用 12px 圆角，控件约 7–8px，状态标签约 5px，保持嵌套关系。浅色只保留轻阴影，深色无需强阴影。图标使用仓库现有的内联 SVG、`currentColor` 和一致线宽；装饰图标隐藏于读屏。

表单使用可见标签，字段下显示具体限制和错误；提交时清楚标识正在运行并防止重复提交。数据尚未准备、运行失败和运行成功没有交易是三种不同状态。回测选择、开始结束日期、手续费和初始资金等应只展示后端真正支持的选项。

回测重点展示累计收益、最大回撤、风险调整指标与交易数量；曲线同时交代资金单位和时间区间。可用基准时提供对照；缺失基准时说明原因。交易分析优先采用表格和有数值标签的条形，不为填充空间而新增图表。图表可访问说明和文字统计必须独立存在，不能只依赖悬浮提示。

## 8. 动效、文案与性能约束

保留 `--dur-fast: 160ms`、`--dur-base: 280ms`、`--ease: cubic-bezier(.22,1,.36,1)`。只在导航选择、表单提交状态、结果出现这三个时刻使用必要反馈。实时数据直接更新，不逐个数字滚动；遵循 `prefers-reduced-motion`，不让动效延迟数据阅读。

文案使用具体动作：“运行回测”“查看交易”“重新加载”；错误解释原因与下一步，例如“当前区间没有可用行情，请调整日期”。演示数据、历史结果和本次运行结果要清楚区分，不把演示指标写成真实收益。

前端工程目标是保持模块职责清楚、请求有生命周期、更新成本可控：

- 导航、数据获取、图表、回测表单各自有清楚边界；DOM 更新集中在所属模块。
- 按当前任务请求和渲染重内容，避免切换后旧请求覆盖新选择；长任务使用后端状态更新，不在主线程做回测计算。
- 对图表点数设合理上限；降采样仅影响展示，统计与下载仍依据完整数据。大表格分页或限制首批行数。
- 定时刷新不重建整个页面；保留用户当前筛选、焦点和滚动位置。页面隐藏时减少无必要轮询。
- 字体和资源优先本地；图表预留高度，加载中不让页面跳动。性能收益必须以测量为准，不写未测量的提速百分比。

## 9. 反面参考与验收

Cash App 的高饱和品牌展示、开场动画和 3D 内容适合品牌体验，本工作台只保留单一强调色的纪律。Backtesting.py 首页完整统计文本适合开发者示例，本工作台应先呈现关键读数，再展开细项；不要把所有统计无层级地堆在首屏。

避免紫蓝渐变模板、等宽卡片墙、无意义徽章、悬浮卡片抬升、emoji 图标和巨型营销标题。继续使用系统可用字体是有意的性能选择，通过数据 / 正文角色及字号对比建立层次。

实施后的验收应覆盖：

- 1440 / 1024 / 390px 浅深主题截图；首屏能够识别当前任务、来源、状态和主要操作。
- 键盘遍历导航、表单与图表控制；焦点可见，标签切换不把焦点留在隐藏内容中。
- 回测正常完成、参数错误、无数据、失败、重复点击和没有交易；状态具有文字说明。
- 切换页面后回测结果仍有明确归属，刷新时间与数据时间不混淆。
- 记录实际加载与交互表现，确认隐藏区域未反复构造大图表，控制台没有异常。

本文提供调研、源码 token 审查和对比度计算结果；不把这些等同于最终页面的浏览器截图验收。实际视觉验证应由实现流程完成并记录。

## 10. 2026-10-04 精修简报：读数优先，七页共用一套尺度

本节在本轮实现前确定设计方向，作为编码和验收依据，不代表下列建议已经全部落地。本次检查读取了 `web_index.html`、`web_theme.css`、`web_workspace.css`、`web_lab.css` 和稳健性视图结构，复用第 2–3 节已有研究，不另起一轮竞品搜集。按 Web Design Scout 的 typography、layout-and-rhythm、components、surface-depth-texture、motion、data-and-dashboard 参考收敛为以下五项。

| 优先级与改进 | 对应现有结构 | 本轮设计决定与验收要点 |
| --- | --- | --- |
| 1. 建立单一首屏焦点 | `.page-heading`、`.overview-strip`、`.metrics-grid`、`.metric-card:first-child` | 工作台标题说明当前任务；将 overview 引导收成较薄的浅青结构带，保留明确的回测入口，避免与深色账户读数同时形成大面积重点。首屏先读到权益与系统状态，其次才是引导文案；不编造收益比较或健康结论 |
| 2. 校准七页导航与空间密度 | `.workspace-sidebar`、`.workspace-nav a`、`.nav-index`、`.sidebar-note`、`.sidebar-footer` | 桌面导航每项约 52–56px，序号固定窄列；当前项使用青绿文字、低饱和表面和稳定细标记。研究流程说明缩短并降低层级，短视窗仍能访问全部七项。移动沿用 `web_lab.css` 已有单行横向滚动，选中项可见，不新增导航抽屉或额外菜单状态 |
| 3. 收束字体与标题基线 | `.eyebrow`、`.panel-heading h2/p`、`.section-heading`、`.field`、`.stat-note`、`.plot-legend` | 中文常读内容不再依赖 9–10px 小字制造密度；字段标签与辅助说明优先 11–12px，正文 13px，区块标题 20px，页面标题 28–36px。英文栏目号保留等宽角色，中文不套用大字距。表单、图表和工具栏的标题基线及顶部间距一致；技术坐标刻度可保持实际 10px |

### 精修 token 契约

已有浅深配色、字体角色和语义色保持不变。以下是建议收束的尺寸角色，实施时应归并进现有变量定义，避免继续增加末尾覆盖规则；名称可与现有 token 合并，但一个角色只保留一个权威定义。

| 角色 | 推荐值 | 应用边界 |
| --- | --- | --- |
| `--font-label` | `11px` | 表单标签、辅助说明、图例；长中文说明可升至 12px |
| `--font-control` | `12px` | 桌面控件文字；移动输入继续保留较大的现有字号 |
| `--font-body-size` | `13px` | 常读正文与档案描述，中文行高 1.65–1.8 |
| `--font-section` | `20px` | 主分析面板标题；面板内部小标题 12–14px |
| `--font-page` | `clamp(28px, 2.4vw, 36px)` | 当前任务标题；不以大标题挤压图表空间 |
| 数据字号角色 | `24–40px` | 主要读数；辅助统计 20–24px，继续使用 `--font-data` |
| `--radius-control` / `--radius-panel` | `7px` / `12px` | 控件与外层面板，状态标签保留约 4–5px |
| `--control-height` | `44px` | 主按钮、表单输入和可点击 summary 的基本高度 |
| 结构节奏 | `4 / 8 / 12 / 16 / 24 / 32 / 48px` | 同组内 8–12px，面板内 16–24px，任务级分隔 24–32px |
| 过渡 | `160ms / 280ms`，现有 `--ease` | 只用于短反馈，动态图表或数字不设置装饰入场 |

主质感继续采用细线和表面明度差。`--bg`、`--surface`、`--surface-soft` 承担常见的三层结构，`--surface-strong` 仅用于必要的局部分组；青绿强调只落在当前任务、主要操作和重要数据。默认保持无重阴影、不发光、不添加玻璃模糊。所有新样式通过本地 CSS class 应用，避免给 SVG 或元素加入与当前 CSP 冲突的 inline style。

### 性能与可访问边界

本轮不新增外部字体、图标包、前端框架、动画库或图表依赖。复用本地字体栈、现有 SVG、原生 `details` 和按需加载的工作区模块；减少叠加覆盖与重复 DOM 更新。控件状态优先用 CSS 和现有事件表达，不为视觉装饰新增轮询、全局 scroll 监听器或持续动画。

七页导航变化不应触发未访问工作区的重请求；主题与 resize 只处理当前可见图表，非活动图保留延迟更新机制。图表降采样保持原始统计不变，坐标标签的可读性不通过增加全部数据节点实现。原生折叠容器可以减少首屏信息量，但不能假定折叠本身已经减少后台请求或计算成本。不要在整个工作区粗暴应用尺寸隔离或延迟渲染，破坏图表量测、键盘定位和深链接。

需要检查的最终效果：1440 / 1024 / 390px 的浅深主题与低动效模式；七个导航入口及当前项可见性；重点读数在灰度下仍有层级；档案和稳健性长内容不撑破页面；表单焦点、错误、空态和展开态可读；无新增外部资源和持续动画；控制台无异常。只有实测才能记录性能收益，本节不作未测量的速度承诺。
